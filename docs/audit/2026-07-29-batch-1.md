- **Top 3 개선점**
  1. 대안 검토 절 추가 — 아키텍처 결정기인데 결정의 반대편이 없다 (**중**)
  2. 수치 전진 배치 + 체감 환산 (**소**)
  3. before/after 비교 시각 1컷 (**중**)
- **퀵윈**: IA·DRY 병기 · W3 문장 2건 분리 · 제목/도입에 "67화면" 삽입

## diff-driven-tc

- **종합 등급**: **B (부분 미달)** — diff→TC 변환 예시는 5편 중 가장 교육적이고 실패담(7건 삭제)도 실측. 그러나 분량 미달, 도입 수치 부재, 방법론 효과의 정량 성과 없음.

| ID | 판정 | 근거 (실제 인용) | 수정 제안 |
|---|---|---|---|
| S1 | FAIL | 배경 3문장, 수치 0 — 티켓 방식의 비용(놓친 회귀 건수, 릴리스당 티켓 수) 미제시 | 도입에 티켓 방식의 실측 비용 1개 + "TC 7건 전부 삭제" 사고를 훅으로 전진 배치 |
| S3 | FAIL | 유일한 실측 "TC 7건"이 시행착오 섹션에 묻힘 | 위와 동일 |
| S4 | PARTIAL | 티켓 산문 기각 서사는 글의 축이나 기각 사유가 정성 | "티켓 N건 vs diff가 추가로 드러낸 변경 N건" 대비 수치 |
| S7 | PARTIAL | 성과 정성 서술. 미완 과제(git 한계)가 마무리에서 회수 안 됨 | 스킵으로 아낀 TC/시간 수치 + git 한계를 다음 과제로 프레이밍 |
| S8 | FAIL | 약 1,700자 — 하한 미달 | "실제 릴리스 적용" 결과 절을 사례 중심으로 확장 (현재 2문장) |
| H3 | FAIL | 수치 0 | 예: "diff 한 덩이에서 TC 3건 —" 식 수치 훅 |
| V1 | PARTIAL | 파이프라인이 텍스트 한 줄뿐 | baseline 원칙 포함 플로 다이어그램으로 |
| E1 | PARTIAL | 방법론의 효과 수치 없음 | 결과 절의 두 제품 사례를 각각 수치로 |
| E3 | FAIL | diff 방식의 대가(코드 접근 권한, diff 독해 비용, 진입장벽) 미언급 | "티켓 대신 diff를 택했다. 대가는 ~다" — '테스터 언어 변환'이 그 대가의 해소책임을 연결 |
| W1/W3 | PARTIAL | "정식 장으로 편입되었고, ~ 됐다" 피동+연결어미 / "그래야 diff = 미검증 분만 남음." 개조식 종결 | "정식 장으로 넣었다. ~가 됐다." / "그래야 diff에 미검증 분만 남는다." |

- **Top 3 개선점**
  1. 결과 정량화 — "테스트를 안 하는 결정도 근거를 갖게 됐다"는 최고 문장 후보인데 숫자가 없어 힘 반감 (**중**)
  2. 실제 릴리스 1건의 diff→TC 전 과정 서사 추가 (**중~대**)
  3. 파이프라인 다이어그램 (**소**)
- **퀵윈**: "편입되었고" 피동 교정 + 문장 분리 · "TC 7건 삭제" 사고를 도입 훅으로 이동 · E3 트레이드오프 1문장

# 배치 1 공통 패턴 (반복 결함)

1. **수치 결핍 체인 (S1→S3→H3→E1→V5) — 가장 치명적.** 도입부 실측 수치 5/5 부재, 제목 수치 5/5 부재, before/after 정량 성과 5/5 부재, 체감 환산 5/5 부재. 모든 결과 섹션이 "완성됐다"류 정성 선언으로 끝남.
2. **분량 미달 (S8) 4/5.** 1,300~1,800자. 원인 동일: 실전 사례가 요약 1~2문장으로 압축 (설계 메모 문체가 블로그로 그대로 이식된 형태). 사례 1개를 장면으로 풀면 분량·E1·E2 동시 해결.
3. **트레이드오프 명시 문장 (E3) 5/5 부재.** 대가에 해당하는 사실은 이미 본문에 있는데 연결만 안 됨 — 대부분 1문장 추가로 해결.
4. **다이어그램 부재 (V1) 4/5.** planner 보드 전경 1장이 유일한 시각 자료.
5. **마무리 '미완 과제(The work ahead)' 전멸 (S7).** 5편 모두 성과 선언 + 경구형 인용구로 종료.
6. **종결 인용구 패턴 동형 반복 (W14 위험).** 5편 전부 `> 경구` 블록쿼트로 종료, 3부작은 구조까지 동일 — 연속으로 읽으면 템플릿 티. 변주 필요.
7. **문체 혼용.** getting-started만 합니다체 — 기본값 위반이거나 '가이드는 존댓말' 예외 명문화 필요.
8. **문장 품질(W)은 전반 양호.** 위반 포스트당 1~2건 (developer 0건). 결함은 문장이 아니라 **구조·신뢰 장치(수치·대안·트레이드오프·미완)**에 집중.

**우선순위 제언**: 전 포스트 공통 "수치 3개(도입 1·성과 1·환산 1) + 트레이드오프 1문장 + 미완 과제 1문단" 패치가 개별 리라이팅보다 효과 큼. C등급 ai-qa-engineer-teammate 사례 확장이 최우선 리라이팅 대상.
