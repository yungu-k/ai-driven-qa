## 1. 중복 판정

기존 발행글 **`field-service-jira-sync`** (2026-07-02) 가 이미 FSM 글이다. 본문 **3,949자 — S8 상한(4,000자) 도달.**
더 못 넣는다. 다루는 것: 배경 · 아키텍처 도식 · P0~P7 로드맵 표 · 연동 원칙 7개 · 접근제어 · 시행착오 5건 · 남은 것.

**성격은 압축본이다.** 각 항목이 한 문단짜리 요약이고, 결정의 근거와 대안 기각 이유가 대부분 빠져 있다.

## 3. 분량 — 한 편에 안 들어간다

사용자 요구 축 4개: 구현 아이디어 / 구현 방식 / Jira 연동 / OAuth.
각 축을 근거까지 풀면 축당 1,500~2,500자 → **합 6,000~10,000자.** S8 분할 검토선(6,000) 초과.

압축해서 한 편에 넣으면 **기존 글과 똑같아진다.** 압축본은 이미 있다.

### 선택지

| 안 | 구성 | 장 | 단 |
|---|---|---|---|
| **(가) 신규 1편 + 기존글 링크** | 신규 = 앱 자체(아이디어·스택·구현·OAuth·접근제어). Jira 연동은 기존 글로 링크 | 스코프 최소. 기존 글 안 건드림 | "Jira 연동 모든 것"은 여전히 압축본으로 남는다 |
| **(나) 신규 1편 + 기존글 개정** (추천) | 신규 = 앱 편. 기존 글에서 배경·스택·P0/P5/P6/P7 을 덜어내고 **Jira 연동 심화편**으로 재편 | 중복이 실제로 사라진다. URL 유지 → SEO 안전. 두 편 다 4,000자 안 | 발행본 수정 |
| (다) 시리즈 3편 | 앱 / Jira 연동 / 보안·OAuth | 축마다 깊게 | 스코프 확대. 기존 글 처리 문제는 그대로 |
