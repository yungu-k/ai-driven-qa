## 논지 — 오너가 직접 줬다 (딴 데서 찾지 않는다)

> **"한 세션이 끝나지 않아도 다른 업무들을 쳐낼 수 있는 구조를 만들기 위함."**

축은 **"막힘을 없애려고 늘렸다"**이지 **"사람이 많으면 좋다"**가 아니다. ★ 오너가 **"생각해보니"**로
썼다 — **하고 나서 이유를 언어화한 것**이고, 그 자체가 정직한 재료다(설계가 먼저 서고, 왜
그랬는지는 나중에 말이 된다).

## 데이터 — 잴 수 있는 것 / 없는 것 (★ 이 가름 자체가 재료다)

| | 상태 | 비고 |
| :--- | :--- | :--- |
| **모델별 토큰** | ✅ 잰다 | 응답마다 input/output/cache 다 남는다. **QA 실측값을 쓴다 — PM 요약 아님** |
| **한도 사건** | ✅ 실재 | 세 세션 동시, "한도 도달, 오후에 자동 재개" 문구. **오너가 말한 "최근" 건과 같은 건인지 QA가 확인** |
| **effort 축** | ❌ 못 잰다 | 기록에 안 남는다(전 응답이 한 값). **긴-effort 구간을 사후에 못 가른다** |
| **기록 구멍** | ⚠️ 반쪽 | 세션 기록이 일부만 — 팀 절반이 안 잡힌다 |

→ **오너가 "model과 effort로 운영했을 때"라고 물었는데 effort 축이 없다. 숨기지 않는다** —
"모델별은 잰다, effort별은 기록이 없어 못 잰다"가 정직한 서술이고 **그 자체가 이 글의 재료**다.
**관측 가능성이 설계에 달려 있다** — 스케일업이 관측을 앞서갔다. 늘리고 나서야 못 재는 축을
알았다(이유를 나중에 안 것과 같은 결).

## 데이터 근거 (QA 실측 · 2026-09-11 11:11 KST 관측)

> 표를 쓸 때마다 **관측 시각·범위**를 붙인다. 자료가 살아 있어(세션들이 지금도 쌓는다)
> 시각 없이 적으면 다음에 잰 사람이 "수가 틀렸다"고 한다.

- **범위:** 이 PC의 세션 전사 32파일, 기간 2026-07-01 ~ 09-11. **전사 루트가 둘이다** —
  WSL 클라이언트(팀 체제 구간)와 Windows 클라이언트(대부분 7~8월 1인 작업기). 🔴 **둘을
  한 표에 섞어 "팀이 이만큼 썼다"로 쓰면 틀린다** — 팀 지표는 WSL 쪽이다. 다른 기계·원격·
  클라우드 세션은 여기서 못 잰다 → 범위를 "이 PC의 팀 세션 전수"로 못박는다. **개인 프로젝트
  세션은 뺐고, 뺐다고 한 줄 적는다.**
- **단위는 "요청"(requestId 유일, 중복 제거)이지 "응답"이 아니다.** 🔴 `assistant` 줄을 그대로
  세면 부푼다(한 요청이 여러 줄). **부푸는 배수가 축마다 다르다** — 요청 수는 약 2배지만
  출력·캐시생성 토큰은 더 크다(긴 응답일수록 줄이 많다) → **한 배수로 보정할 수 없다. 정본은
  언제나 중복 제거 후 값만 쓴다.** "Claude가 답한 횟수"로 읽히는 수는 전체 **약 2.2만 / WSL 팀 약 1.2만**.
- **토큰 네 종(입력/출력/캐시생성/캐시읽기)은 절대 한 칸에 더하지 않는다 — 단가가 다르다.**
- ★ **캐시읽기가 전체의 약 98%다**(정정 후에도 유지 — 관찰이 살아남았다). "토큰을 돈으로
  본다"에 정직하게 답하면 **입력 ≈30만 대 캐시읽기 ≈100억**이고(3만 배 차), **두 수를 더하면
  그 대비가 사라진다.** 이 대비가 이 글에서 제일 센 수.
- ★ **"토큰이 많다"는 한 뜻이 아니다 — 만든 것과 읽은 것은 반대로 움직인다.** 출력·캐시생성은
  그 요청이 **새로 만든 양**(일을 많이 하면 커진다), 캐시읽기는 **읽은 컨텍스트 크기**(한 턴
  안에서 거의 일정하고, 도구 없이 한 번에 답한 요청이 가장 무겁다). **우리 소비의 98%는
  "만든 것"이 아니라 "읽은 것"**이다 — 오너 "토큰을 돈으로 본다"에 **이 구분이 글의 요점이 될 수
  있다.** (입력은 절대량이 작고 0.8%의 요청이 그 12%를 만드는 얇은 표본이라 이 대비에서 뺀다.
  ⚠️ 단가로 넘어가지 않는다 — 요금 보류.)
- **표 각주(그대로 붙인다):** "왜 첫 줄만 세나 — 같은 요청이 여러 줄로 저장되고(61.8%, 최다
  6줄) 그 줄들의 사용량이 전수에서 동일하다(어긋난 건 0) → 합산이 아니라 대표값. 레코드를
  그대로 더하면 축에 따라 1.98~3.00배 부푼다(입력의 3.0배는 0.8%의 요청이 입력의 12%를 만드는
  얇은 표본이라 흔들리는 수 — 캐시읽기 1.98은 구조다)."
- **한도 사건:** 세 세션이 **94초 안에** 연달아 튕겼고 전부 같은 날이다 →
  **한도는 세션 단위가 아니라 계정 단위 공유 자원**이다. ★ 스케일업 글의 핵심 — 늘린 게
  처리량만이 아니었다(공유 한도도 같이 눌렀다).
- **effort 축:** 전사에 없다(속도·티어가 전 응답 한 값). 지금 설정은 상위 effort지만 **그 기록이
  사건보다 10시간 뒤**라 "사건 당시 그 값이었다"고 못 쓴다. 도입 시점은 "8월 이후 어느 사이"까지가 한계.
- **구멍:** 요청이 0인 날이 있다 → "매일 늘었다"류 문장은 그 구멍에서 틀린다.
- **단가·요금:** 모델 가격은 **기억으로 쓰지 않고** 공식 자료를 확인해 넣는다. 🔴 세션이 남기는
  누적 비용값은 **32세션 중 13개에만 있고 레코드 합과 1.4~1.6배 어긋난다(이유 미상)** — 지금
  요금을 쓰면 틀린다. **돈으로 말할 거면 QA 실측을 다시 받는다.**

### 근거표 — 도구 호출 수별 평균 (WSL 팀 세션 · 2026-09-11 11:28 KST 관측 · 12,083 요청 · 중복 제거)

   설정으로 돌고 있었나"의 정황**으로만 쓰고 **원인으로 쓰지 않는다.**
2. **"N 토큰 쓰면 한도"** — 반례가 있다. **3.7배 더 큰 5시간 창이 안 걸렸다**(걸린 창은 더 싼
