# About → 이력서 PDF — 배치·구성 v1

> 오너: 「About 쪽에 **PDF 추출 기능** 넣어서 이력서 관심있는 사람들이 PDF로 발급받아서
> 가게 할 수 있어? **PDF 내용 배치나 구성 등은 디자인 세션이랑 상의**해봐.」

**「할 수 있어?」에 먼저 답한다: 된다. 그리고 싸다** — **CSS 약 40줄, 새 HTML 0, 새 의존성 0.**
**구현은 dev/tw.** 여기는 배치·구성까지다.

---

## 0. 🔴 먼저 — **쟀다. 산술이 아니다**

배포된 About 을 `print` 매체로 렌더해 **실제 PDF 로 뽑고 쪽수를 셌다**(A4, 여백 14/15mm,
본문 높이 **1017px/장**).

| 단계 | 쪽 | main 높이 | 섹션별(헤더·Career·강점·원칙·인용) |
|---|---|---|---|
| 지금 그대로 | **3쪽** | 2475px | 340 · **1390** · 318 · 295 · 84 |
| 면·배경만 제거 | 3쪽 | 2384px | 340 · 1369 · 318 · 272 · 84 |
| **+ 유틸리티 압축** | 🔴 **2쪽** | **1575px** | 227 · **958** · 185 · 166 · 39 |
| + 인용 배너 제거 | 2쪽 | 1536px | 227 · 958 · 185 · 166 · 0 |

**Career 가 전체의 56%**다. 분량을 정하는 것은 그 섹션이다.

---

## 1. 경로 — **A(인쇄 CSS + `window.print()`)**. 배치가 그 선택을 **더** 지지한다

PM 이 A~D 를 적고 「배치를 다르게 가져가면 A 가 불리해진다」고 했다.
⇒ **다르게 안 가져간다.** 필요한 건 **배치 변경이 아니라 제약 변경**이다:
**면을 빼고, 글자를 줄이고, 간격을 좁히고, 쪽 나눔을 막는다.** 전부 **같은 HTML 위 CSS**다.

🔴 **그리고 A 에는 PM 목록에 없는 이유가 하나 더 있다 — 오늘 우리가 종일 잡은 것이다.**
**B·C·D 는 전부 두 번째 렌더 경로를 만든다.** 그러면 **About 을 고칠 때마다 PDF 도 고쳐야** 하고,
**한쪽만 고쳐지는 날이 온다**(오늘 이 형태가 다섯 번 나왔다: `.bak`↔`.tmp` · 정본 경로 ·
문안 · 조건식 · 층 사이). **A 는 출처가 하나다.**

⚠️ **A 의 값은 「사용자가 「PDF로 저장」을 한 번 고른다」**이고, **그건 표시로 줄인다**(§6).

---

## 2. 분량 — **A4 2장.** 1장은 내용을 버려야 한다

```
2장 가용 2034px  ·  압축 후 1536px  ⇒ 여유 498px
1장 가용 1017px  ·  Career 하나가 958px  ⇒ 나머지를 다 버려도 겨우 든다
```
**1장 이력서는 관행이지만 여기선 내용을 버리는 값이다.** ⇒ **2장.**
**여유 498px 은 §5 의 URL 줄과 §7 의 빈칸을 받고도 남는다.**

### 2-1. 🔴 **글 목록은 안 싣는다**

33편을 종이에 못 넣는다. **고르면 「왜 이 다섯인가」를 설명해야 하고 그건 이력서가 아니라
포트폴리오**다. ⇒ **블로그 자체가 그 목록이다. URL 한 줄이 33편을 대신한다.**

⚠️ **넘칠 때 줄이는 순서**(위에서부터): **인용 배너 → 칩 → 역할당 불릿 3개 상한**.
**Career 의 역할은 안 지운다** — 이력서에서 **빠진 기간은 질문이 된다.**

---

## 3. 🔴 흑백 — **색을 정보로 안 쓴다. 0색이다**

받는 쪽은 대개 인쇄한다. 오늘 내가 세운 **「흰 배경 위 마크로 3:1 을 지키며 나눌 수 있는
상태는 최대 둘」**이 여기서는 더 세게 걸린다 — **이력서에 「상태」가 없다.** 색이 나를 것이 없다.

| 지금 | 인쇄 |
|---|---|
| `text-accent` 강조 | **굵기로**(`font-weight:700`), 색은 먹 |
| `bg-muted/40` 카드 면 | **없앤다** — 흑백에서 회색 면은 **잉크만 먹고 구분은 약하다** |
| `border-accent` | **먹선** |
| `rounded-xl` | **각지게** — 인쇄물에서 둥근 모서리는 화면 문법이다 |

---

## 4. 링크 — **URL 을 글자로. QR 은 안 쓴다**

종이에서 링크는 죽는다. ⇒ **보이는 글자로 적는다.**
```
GitHub    github.com/<계정>
LinkedIn  linkedin.com/in/<계정>
블로그     <도메인>            ← 33편이 여기 있다
```
**도메인+경로까지만.** `https://` 와 쿼리는 **노이즈**다.

⛔ **QR 을 안 쓰는 이유 셋**: ① **무엇으로 가는지 사람이 못 읽는다**(이력서에서 불신을 산다)
② 스캐너가 필요하다 ③ **흑백·저해상 인쇄에서 깨진다**. **URL 은 셋 다 없다.**

---

## 5. 인쇄 배치 — **빼는 것과 바꾸는 것**

**빼는 것**(전부 화면 장치): 헤더 내비 · 푸터 · 테마 토글 · 검색 · 「맨 위로」 · **인용 배너**.
⚠️ **인용 배너는 블로그의 목소리지 이력서의 자격이 아니다.**

**바꾸는 것**: §3 의 면·색·모서리, 그리고 **쪽 나눔** —
```css
section > div > div, li { break-inside: avoid; page-break-inside: avoid; }
```
🔴 **한 역할이 쪽을 넘어 잘리면 경력이 잘린 것처럼 읽힌다.**

### 5-1. ⚠️ 구현 함정 — **`body{font-size}` 로는 안 줄어든다**

**내 첫 초안이 그래서 실패했다**(3쪽 → 3쪽, 204px 만 줄었다).
**Tailwind 가 자식 요소에 크기를 직접 박아서** 상위 규칙이 안 먹는다.
⇒ **유틸리티를 직접 겨냥해야 한다**: `.text-sm` · `.text-base` · `[class*="p-4"]` ·
`[class*="space-y-4"]>*+*` · `[class*="gap-3"]` …

🔴 **그래서 유지가 약하다** — 누가 `text-sm` 을 `text-[13px]` 로 바꾸면 **인쇄가 조용히 되돌아간다.**
**빨강이 안 난다.** ⇒ §8 의 쪽수 검사가 **그 자리의 유일한 그물**이다.

### 5-2. 파일 이름 — **`<title>` 이 그대로 파일명이 된다**

`window.print()` 로 저장하면 브라우저가 **`document.title` 을 파일명**으로 쓴다.
지금은 「About | …」 이라 **`About.pdf`** 가 된다. ⇒ **버튼이 인쇄 직전에 제목을 바꾸고
끝나면 되돌린다.** 🔴 **문서 이름은 내용의 일부다** — 받는 사람 폴더에 그 이름으로 남는다.

---

## 6. 버튼 — **한 줄로 기대를 맞춘다**

A 의 유일한 마찰은 **「대상 프린터」에서 「PDF로 저장」을 골라야 한다**는 것이다.
⇒ **버튼 옆에 그 사실을 적는다.**
```
[ 이력서 PDF 받기 ]   인쇄 창에서 「PDF로 저장」을 고르세요 · A4 2장
```
⚠️ **「A4 2장」을 적는 이유**: 받는 사람이 **몇 장인지 알고 누른다.**
**모르고 누르면 3장이 나와도 모른다** — 그게 §8 검사가 지키는 값이기도 하다.

---

## 7. 🔴 빈칸 둘 — **오너 결정. 내가 안 정한다**

배치는 **자리를 비워 두고** 그린다. 오너가 정하면 채운다.

| 빈칸 | 자리 | 비면 |
|---|---|---|
| **연락처** | 헤더 오른쪽, URL 줄 아래 | **그 줄을 안 그린다**(빈 라벨을 남기지 않는다) |
| **회사명** | Career 각 덩어리의 제목 | 지금 값 그대로 |

### 7-1. ⚠️ PM 에게 — **부딪힘이 생각보다 좁다. 쟀다**

> 「이 블로그는 익명화가 원칙인데 이력서는 보통 회사명을 적는다 — **정면으로 부딪힌다**」

**About 본문(INTRO)에 이미 재직사 셋이 실명으로 공개돼 있다.**
익명화가 걸려 있는 것은 **재직사가 아니라 고객사·제품**이다(「글로벌 대형 카지노」·「무인 장비」).

⇒ **오너에게 물을 것은 둘로 갈린다:**
1. **현재 재직사명을 적나** — 지금 About 에도 안 적혀 있다(업종만)
2. **고객사를 적나** — 🔴 **이건 익명화 원칙과 진짜로 부딪힌다.** 그리고 **공개 PDF 다**

**1 과 2 를 한 질문으로 묶어 올리면 답이 하나로 온다.** 갈라서 올려라.

## 8. 검사 — 🔴 **인쇄는 「몇 쪽인가」로 잰다**

| # | 검사 | 빨강 |
|---|---|---|
| **R1** | 🔴 **A4 2쪽이다** | 유틸리티 압축 CSS 를 지우면 3쪽 — **실측으로 확인했다** |
| **R2** | 화면 장치가 **안 실린다**(내비·푸터·토글·검색·버튼) | 하나 남기면 빨강 |
| **R3** | **색이 0개** — 먹과 회색조뿐 | `text-accent` 를 되살리면 빨강 |
| **R4** | 역할 덩어리가 **쪽을 안 넘는다** | `break-inside` 를 지우면 빨강 |
| **R5** | 링크가 **글자로 보인다** | URL 텍스트가 없으면 빨강 |
| **R6** | 저장 파일명이 **이력서 이름** | 제목 교체를 지우면 빨강 |
| **R7** | ⚠️ **버튼 문구의 쪽수와 실제 쪽수가 같다** | 하나만 바꾸면 빨강 |

🔴 **R1 과 R7 이 이 건의 본체다.** **R1 은 유지가 약한 자리(§5-1)의 유일한 그물**이고,
**R7 은 「두 자리에 같은 수를 적는다」를 검사로 막는다** — 오늘 다섯 번 나온 형태다.

**재는 법**: Playwright `emulateMedia({media:"print"})` → `page.pdf({format:"A4"})` →
**PDF 안의 `/Type /Page` 수를 센다.** 브라우저 없이 안 된다 —
**「그려졌나」를 재는 도구로는 「몇 쪽인가」가 안 나온다.**

## 9. 최소안 / 권고안

**최소안** — **오늘 나갈 수 있다.**
1. `@media print` 블록 하나(§3·§5·§5-1) · 2. About 에 버튼 하나(`window.print()`) ·
3. 버튼 옆 한 줄(§6) · 4. 링크 URL 글자 노출(§4) · 5. 검사 **R1**

**권고안** — 한 바퀴 뒤
6. 제목 교체로 파일명(§5-2) · 7. 검사 R2~R7 · 8. 연락처 줄(오너가 정하면)

⛔ **권고안에도 안 넣은 것**: 인쇄 전용 표지·QR·사진 프레임·워터마크.
**이력서에 장식을 더하는 것은 이 요구에 없다.**

## 10. 안 정한 것
- **연락처·회사명 둘**(§7) — 오너
- **제목(파일명) 문안** — §7 이 정해지면 같이 정한다
- **글꼴** — 지금 화면 글꼴을 그대로 쓴다고 가정했다. **인쇄 전용 글꼴은 안 쟀다**
