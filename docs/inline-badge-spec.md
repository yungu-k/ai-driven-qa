# 본문 인라인 배지 규격 v1

작성: 디자이너 세션, 2026-09-10. 계기는 「신규 팀원 표시가 다크에서 안 보인다」(tw 전달).
적용 대상: 마크다운 본문·표 안에 들어가는 **작은 상태 표시**(신규·보류·폐기 등).
아이콘·도해는 해당 없음 — 그쪽은 `diagram-spec.md`.

## 1. 결정 — 이모지가 아니라 텍스트 배지

**이모지를 쓰지 않는다.** 대신 `<span>` + CSS 배지를 쓴다.

이모지가 안 보이는 이유는 크기가 아니라 **테마에 참여하지 않기 때문**이다.
🆕 는 열람자 OS의 컬러 이모지 폰트가 그리는 **고정 색 비트맵**이라,
- 사이트 테마(`data-theme`)를 따라가지 못한다 — 다크 지면에 라이트용 파란 사각형이 그대로 얹힌다
- 실측: 표 셀(14px)에서 배지 글자가 **높이 6~7px**로 렌더된다. 다크에서는 파란 얼룩으로만 읽힌다
- 플랫폼마다 모양이 다르다(Windows Segoe UI Emoji / Apple / Noto). 검수한 화면과 독자 화면이 다르다
- 글리프가 없는 환경에서는 두부(tofu)가 된다

텍스트 배지는 이 네 가지가 전부 사라진다. **CSS가 없는 환경(RSS 리더·읽기 모드)에서도
「신규」라는 글자가 그대로 남아 뜻이 보존된다** — 이모지는 그 자리에서 뜻을 잃는다.

## 2. 마크업 규약

마크다운 표 안은 인라인 HTML만 되므로 `<span>` 하나로 끝낸다.

```html
| PM<span class="badge badge-new">신규</span> | 지시 라우팅·일정 추적 | … |
```

- **이름과 붙여 쓴다.** 앞 공백을 넣지 않는다 — 간격은 CSS `margin-inline-start`가 준다
- 클래스는 **두 개**다: `badge`(모양) + `badge-new`(색). 나중에 다른 표시가 필요하면
  `badge-*` 색 규칙 2줄만 추가한다
- 배지 글자는 **뜻을 담은 한국어 한 단어**. 색만으로 구분하지 않는다(색맹·흑백 인쇄)

## 3. CSS — `src/styles/typography.css` 말미에 추가

```css
/* 인라인 배지 — 본문·표 안의 작은 상태 표시 (docs/inline-badge-spec.md) */
.badge {
  display: inline-block;
  margin-inline-start: 0.35em;
  padding: 0.1em 0.45em;
  border-radius: 0.4em;
  font-size: 0.75rem;
  font-weight: 700;
  line-height: 1.5;
  vertical-align: 0.08em;
  white-space: nowrap;
}
.badge-new {
  background: var(--accent);
  color: var(--accent-foreground);
}
```

- 색은 **테마 토큰만** 쓴다(`theme.css`). 임의 hex 금지 — 토글이 자동으로 따라온다
- 크기는 `em`이 아니라 **`0.75rem` 고정(=12px)**이다. 표는 프로즈의 `0.875em`이라
  `em`으로 잡으면 표 안에서 11px 밑으로 내려간다. 12px가 본문 최소 글자 크기다
- `white-space: nowrap` — 「신규」가 줄바꿈으로 갈라지지 않게

## 4. 대비 실측 (WCAG 상대휘도)

| 조합 | 대비 | 기준 |
|---|---|---|
| 라이트 — `#ffffff` 글자 / `#4f46e5` 면 | **6.29:1** | 통과(4.5 이상) |
| 다크 — `#0b0e14` 글자 / `#8b93ff` 면 | **7.10:1** | 통과 |
| 라이트 — 배지 면 vs 지면 `#fafafa` | 6.02:1 | 형태가 또렷이 읽힘 |
| 다크 — 배지 면 vs 지면 `#0b0e14` | 7.10:1 | 〃 |

굵은 12px는 18.7px 미만이므로 **4.5:1 기준**을 적용했다(3:1 완화 대상 아님).

### 기각한 대안

| 안 | 대비 | 기각 이유 |
|---|---|---|
| 틴트 면 + 강조 글자 | 5.39:1(L) / 5.84:1(D) | 글자는 통과하나 **면 대비가 1.12:1**이라 라이트에서 배지 형태가 사라진다 — 「안 보인다」가 반쯤 남는다 |
| 테두리만(투명 면) | 6.02 / 7.10 | 읽히긴 하나 1px 선이라 채움보다 약하다. 표에 여러 개 놓이면 눈에 안 걸린다 |

## 5. 쓰는 규칙

- **조사가 붙는 자리에 쓰지 않는다.** 「loganalyst<배지>가 로그를 맡는다」는 배지가 이름과 조사
  사이에 끼어 읽기가 끊긴다. 배지는 **표 셀·목록 항목처럼 조사가 안 오는 자리**에 쓴다
- **떼는 조건을 같이 정한다.** 「신규」는 상태지 이름이 아니다. 조건 없이 붙이면 시간이 지나
  거짓말이 된다. 발행 글처럼 **특정 날짜의 스냅샷**이면 그대로 두고, 상시 목록에 쓸 때는
  「합류 N주 이내」 같은 기준을 문서에 적는다
- 한 표에서 배지가 **절반을 넘으면** 배지를 빼고 열을 하나 만든다. 표시는 소수일 때만 표시다

## 6. 확인 방법

바꾼 뒤 **두 테마를 다 열어서 본다**(대비 계산만으로 끝내지 않는다).

```bash
# 미리보기 페이지를 라이트/다크 두 섹션으로 만들고 섹션별 캡처
cmd.exe /c "set NODE_PATH=%USERPROFILE%\Desktop\QA\fsm\node_modules&& node shot.cjs"
```

같이 잰다: **배지가 있는 행과 없는 행의 높이 차**. 이번 실측은 33~35px로
배지 유무와 무관한 반올림 편차였다(배지 상자 높이 20px < 줄상자 21px).
배지가 행 높이를 밀면 표가 들쭉날쭉해진다 — 그때는 `line-height`를 줄인다.
