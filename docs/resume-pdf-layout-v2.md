# About → 이력서 PDF — 배치·구성 v2

> 오너 2026-10-12: 「디자인적인 결정이 맞아? **요즘은 인쇄가 아니라 다 웹으로 그냥 보는 사람이
> 많을 텐데**」 → 「**색상은 적당히 써도 돼. 세련된 디자인의 이력서처럼 보이고 싶어**」

v1 을 **폐기하지 않고 전제만 갈아 끼웠다.** 배치·분량·검사 틀은 v1 이 세운 그대로다.

---

## 0. 🔴 바뀐 것은 디자인이 아니라 **전제**다

v1 §3 은 「**받는 쪽은 대개 인쇄한다**」 한 문장 위에 서 있었다. **그 문장을 안 쟀다.**
이력서 PDF 가 실제로 열리는 자리는 메일 첨부·ATS 뷰어·링크드인 — **화면**이다.
전제가 틀리면 그 위의 결론(0색·장식 금지·URL 을 글자로만)이 **전부 같이 틀린다.**

⚠ 그렇다고 **인쇄 가능성이 0 이 되지는 않는다**(면접장 출력). ⇒ 제약은 둘로 갈린다.

| | v1 | v2 |
|---|---|---|
| 1차 소비 | 종이 | **화면** |
| 색 | **0색** | **팔레트 4색**, 단 색이 **정보를 나르지 않는다** |
| 면(배경) | 없앤다 | **금지**(이유가 다르다 — §2-2) |
| 링크 | 글자로만 | **글자 + `href`**(§5) |
| 분량 | A4 2쪽 | A4 2쪽 (유지) |
| 글자 하한 | 전부 9pt | **본문 9pt · 메타 8.25pt**(§3) |

## 1. 색 — **쓴다. 단 색이 정보를 나르지 않는다**

팔레트는 블로그 도해 규격(`docs/diagram-spec.md` §4)에서 가져온다. **새 색을 만들지 않는다** —
이력서와 블로그가 같은 색을 쓰면 그 자체가 한 벌로 읽힌다.

| 역할 | 값 | 흰 배경 대비(실측) | 쓰는 자리 |
|---|---|---|---|
| 먹 | `#1c1c21` | 16.3:1 | 본문·제목 전부 |
| 보조 | `#62656e` | 5.1:1 | 기간·맥락·칩·섹션 라벨 |
| 강조 | `#4f46e5` | 6.0:1 | **연락 줄 링크 · 회사 사이트 링크 · 불릿 마커 · 섹션 강조 단** |
| 장식선 | `#e4e4e9` | 1.2:1 | 섹션 밑줄·사진 테두리 **(의미 있는 선에 금지)** |

### 1-1. 「색이 정보를 나르지 않는다」의 뜻 — 검사로 적는다

강조색이 쓰인 **네 자리는 전부 같은 역할**(「여기를 누를 수 있다」·「항목이 시작된다」)이고,
**흑백으로 떨어뜨리면 회색 하나로 수렴해도 잃는 정보가 0** 이다. 상태·등급·경고를 색으로
나누기 시작하는 순간 이 성질이 깨진다 ⇒ **R3c 가 강조색 사용처를 화이트리스트로 묶는다.**

### 1-2. 🔴 면(배경)은 **쓰지 않는다** — v1 과 결론은 같고 이유가 다르다

v1: 「흑백에서 회색 면은 잉크만 먹는다」 / **v2: 브라우저 인쇄는 「배경 그래픽」이 기본 꺼짐이라
틴트 카드가 받는 쪽에서 통째로 사라진다.** 면에 정보를 실으면 **그 정보가 없어진다.**
⇒ 색은 **글자와 선**에만. 테두리는 그 설정과 무관하게 찍힌다(강조 단을 `background` 가 아니라
`border-bottom` 으로 그리는 이유다 — 첫 판이 그래서 안 찍혔다).

## 2. 타이포 — 6단, 하한은 둘

| 자리 | 크기 | 굵기 |
|---|---|---|
| 이름 | 25px | 800 |
| 회사 | 15px | 700 |
| 역할 제목 | 13px | 700 |
| 본문·불릿·소개 | **12.5px(9.4pt)** | 400 |
| 맥락·기간·회사 사이트 | 11.5px | 400 |
| 섹션 라벨·칩·URL 줄 | 11px(8.25pt) | 700/400 |

🔴 **하한을 둘로 가른 것은 완화다. 그래서 적는다** — 정독하는 글(본문)은 **12px(9pt)**,
훑는 글(메타·라벨)은 **11px(8.25pt)**. 11px 아래는 **없다**(R8 이 두 단을 따로 잰다).

**굵은 글자는 16.5%**(실측). v1 은 선택자 사고로 **100%** 였다 — 전부 굵으면 강조가 죽는다(R10).

## 3. 배치 — **상자를 벗기고 여백·규칙선·들여쓰기로 가른다**

v1 은 화면 카드(`rounded-xl border bg-muted/40`)를 그대로 종이에 옮겨서 **블록마다 사각 상자**가
찍혔다. 상자가 많으면 서식 문서처럼 읽힌다.

- **머리**: 사진 80px(각진 1px 장식선) · 이름 · 한 줄 요약 · **URL 줄**
  ⛔ 칩 줄(연락 버튼 + 자격 요약 칩)은 **안 싣는다**(오너 2026-10-12) — 칩의 내용은
  바로 아래 소개 문단과 경력이 이미 말한다
- **섹션 제목**: 11px/700/자간 0.08em + **밑줄 1px(장식선)** + 왼쪽 **강조 단 24px**
  (v1 은 섹션 제목이 페이지에서 **가장 작고 흐렸다** — 위계 역전이었다)
- **경력**: 회사(15px) → 역할(13px, **11px 들여쓰기**) → 불릿. 회사 사이는 **선이 아니라 여백 15px**
  ⚠ 회사 사이를 선으로 가르면 쪽이 넘어갈 때 **그 선이 2쪽 맨 위에 외톨이로 뜬다**(실측)
- **강점·원칙**: 2열, 상자 없음, 제목 12.5px/700 + 설명 11.5px 보조색
- 한글에 `tracking-widest`(1.2px)는 자간만 벌어진다 ⇒ 0.08em

**측정**: main 1574px · **A4 2쪽** · 2쪽 충전 ~55% · PDF 링크 주석 20개.

## 4. 구현 — 유틸리티가 아니라 **구조를 겨냥한다**

v1 §5-1 의 약한 자리(`.text-sm`·`[class*=p-4]` 를 직접 누름)를 **`r-*` 인쇄 손잡이**로 바꿨다.
마크업에 `r-head`·`r-name`·`r-h2`·`r-company`·`r-role`·`r-bullets`·`r-card` 를 달고
인쇄 CSS 는 그 이름만 본다. **화면 스타일은 0** — 손잡이는 인쇄에서만 뜻을 가진다.

---

## 5. 링크 — **글자로 적고, 누를 수 있게 둔다**

v1 은 「종이에서 링크는 죽는다 ⇒ 글자로」까지만 갔다. 그래서 **URL 줄은 `<p>` 라 안 눌렸고**,
정작 화면 장치로 둔 칩에는 링크가 살아 있었다 — **뒤집혀 있었다.**
v2 는 URL 줄을 `<a>` 로 둔다: 보이는 글자는 도메인+경로, `href` 는 실제 주소.
본문 속 글 링크는 **먹 글자 + 장식선 밑줄**로 조용히 둔다(강조색은 연락 줄에만).

⛔ QR 은 여전히 안 쓴다(무엇으로 가는지 사람이 못 읽는다).

## 6. 사진 — 매체로 가른다 (오너 결정 2026-10-12)

화면 About = 블로그 정체성(뒷모습 풍경) / **PDF = 이력서 사진**(`public/images/resume-photo.jpg`,
600×600, EXIF 제거). 같은 자리에 두 장을 겹치고 `no-print`/`print-only` 로 가른다.
인쇄용은 `loading="eager"` — `lazy` 면 화면에서 `display:none` 이라 **안 받아 오고 인쇄엔 늦는다.**

### 8-1. 2번은 **UI 겹침이 아니라 내용 중복**이다

머리에서 **경력 길이와 직함이 세 번** 나온다:
`공윤구`(25px 이름) → `경력 8년 6개월 QA 엔지니어 · …`(한 줄 요약) → `**공윤구** — 경력 8년 6개월
QA 엔지니어입니다. …`(소개 첫 문장). 요소가 서로를 가리는 것은 없다 — **같은 말을 세 번 한다.**
화면 About 도 같은 상태다.

- ⛔ A. 그대로 둔다 — **기각**(오너 2026-10-12: 「실제로 이 부분에서 공윤구는 빼도 되겠어」)
- ✅ B. **소개 첫 문장을 이름 없이 시작한다**(화면·PDF 공통) — **tw 가 반영**(`675a9ac`, 2026-10-12).
  문장이 `${CAREER_LABEL} QA 엔지니어입니다. …` 로 시작한다(계산값 보존 확인).
  ⚠ **남은 중복 1회**: 한 줄 요약(「경력 8년 6개월 QA 엔지니어 · …」)과 소개 첫 문장이 같은
