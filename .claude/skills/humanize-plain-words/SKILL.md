# humanize-plain-words — 쉬운 말로 다시 쓰기

**규칙의 정본은 `docs/HUMANIZE_PLAIN_WORDS.md` 하나다.** 이 스킬은 순서만 적는다. 시작할 때 그 파일을 끝까지 읽는다.

## 한 편을 퇴고할 때
1. 정본 §1(독자·표준 용어 표)과 §3(규칙 11개)을 읽는다.
2. 1단계를 먼저 통과시킨다: `python3 scripts/ai-tells.py src/content/posts/<slug>.md`
3. 정본 §8 의 다섯 질문으로 글을 훑고, 걸린 **문단**을 다시 쓴다(문장 하나만 고치지 않는다).
4. 풀이에 쓸 사실은 정본 §5 순서로 찾는다. 공개 글 → 원자료 grep → 그래도 없으면 쓰지 않는다. Dean 에게 사실을 묻지 않는다.
5. 바꾸지 않는 것(정본 §4)을 기계로 확인한다: `python3 scripts/edit-invariants.py src/content/posts/<slug>.md`
   - 분량 110% 초과로 나오면, 2단계에서는 130% 까지 괜찮다. 「인용 바뀜」은 글쓴이 조어를 지운 것인지 본다.
6. 가능하면 읽기 검사자 1명(「개발을 모르는 고등학생」 역할)에게 고친 문단을 자기 말로 설명하게 한다. 막힌 낱말이 업계 표준 용어뿐이면 통과다.

## 여러 편을 한꺼번에(전수) 볼 때
정본 §7 의 일곱 단계를 따른다. 감사 → 병렬 다시 쓰기(사본에) → 기계 검사 → 독립 사실 대조 → 읽기 검사(고치기 전/후를 가려 엇갈려 배정) → Dean 가린 표본 → 반영·배포.

## 꼭 피할 것 (2026-11-23 1차 교정이 폐기된 이유)
- 조어 옆에 또 다른 압축 풀이를 덧대기. ✗ 「실측에 맡겨 흐려 둔」
- 업계 표준 용어(커밋·세션·QA·diff 등)에 풀이 붙이기
- 「결함이 없다」를 「쉽다」로 여기기. 기준은 **독자가 평소 쓰는 말인가**다.
